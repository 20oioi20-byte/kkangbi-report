# K2. 데이터 사전

> Copilot 에이전트 지식 문서 2/5 · 데이터가 **어디에, 어떤 이름으로** 저장되는지 정의한다.
> 저장소는 SharePoint 사이트 "센터리포트"의 목록(List)과 문서 라이브러리이다.

## 1. 목록 구성
| 목록 이름 | 내부 이름 | 용도 | 한 행의 의미 |
|---|---|---|---|
| 센터 | Centers | 센터 기본정보 | 센터 1곳 |
| 일별실적 | DailyMetrics | 일별 실적·근태 값 | 센터 × 일자 × 지표 1개 |
| 월별TO | MonthlyTO | 월별 정원 | 센터 × 연월 |
| KPI목표 | KpiTargets | 핵심지표 목표값 | 센터 × 지표 × 연월(또는 "기본") |
| 이슈 | Issues | 이슈·히스토리 | 이슈 1건 |
| 공휴일 | Holidays | 쉬는 날 | 날짜 1개 |
| 알림설정 | NotifySettings | 미업로드 알림 설정 | 알림 종류 1개 |
| 알림로그 | NotifyLog | 알림 발송 이력 | 발송 1건 |
| 결재요청 | ApprovalRequests | 문서결재 이력 | 요청 1건 |
| 업로드자료함(라이브러리) | Uploads | 원본 파일 보관 | 파일 1개 |

| 정렬순서 | SortOrder | 숫자 | |

### 2-2. 일별실적 (DailyMetrics) — 핵심 목록
| 열 | 내부 이름 | 형식 | 설명 |
|---|---|---|---|
| 키 | Title | 한 줄 텍스트(고유, 색인) | `센터코드\|YYYY-MM-DD\|지표키` — 같은 키는 덮어쓴다 |
| 센터코드 | CenterCode | 한 줄 텍스트(색인) | |
| 일자 | ReportDate | 날짜(색인) | |
| 구분 | MetricGroup | 선택 | 근태 / 실적 |
| 지표키 | MetricKey | 한 줄 텍스트(색인) | 아래 3장 |
| 값 | Value | 숫자(소수 2자리) | 계산용 숫자. 시간은 **초**, 비율은 **%값**(97.5) |
| 원본값 | RawValue | 한 줄 텍스트 | 파일에 적힌 그대로(예: "1,348", "4:00:00", "97.5%") |
| 출처 | Source | 선택 | 엑셀자동 / HWPX자동 / 근태파일 / 직접입력 / 이관 |
| 원본파일 | SourceFile | 한 줄 텍스트 | 업로드자료함 파일 경로 |

규칙
- **0은 값이다.** 빈칸(값 없음)과 0을 구분한다. 값이 없는 지표는 행을 만들지 않는다.
- 실적과 근태는 **서로 덮어쓰지 않는다.** 실적만 저장하면 근태 행은 그대로 남는다(구분 열로 분리).
- 같은 센터·일자·지표를 다시 올리면 새 값으로 바뀐다(키 기준 덮어쓰기).

### 2-3. 월별TO (MonthlyTO)
| 열 | 내부 이름 | 형식 |
|---|---|---|
| 키 | Title | `센터코드\|YYYY-MM` |
| 센터코드 | CenterCode | 텍스트 |
| 연월 | YearMonth | 텍스트 `YYYY-MM` |
| 관리자TO | ManagerTO | 숫자 |
| 상담사TO | CounselorTO | 숫자 |

### 2-4. KPI목표 (KpiTargets)
| 열 | 내부 이름 | 형식 | 설명 |
|---|---|---|---|
| 키 | Title | 텍스트 | `센터코드\|지표키\|연월` (기본 목표는 연월 자리에 `기본`) |
| 센터코드 | CenterCode | 텍스트 | |
| 지표키 | MetricKey | 텍스트 | 3장의 지표키 또는 K4의 계산지표 |
| 지표명 | MetricLabel | 텍스트 | 화면 표시 이름 |
| 연월 | YearMonth | 텍스트 | `YYYY-MM` 또는 `기본` |
| 목표값 | TargetValue | 숫자 | 시간 지표는 **초**(4:00:00 → 14400) |
| 정렬순서 | SortOrder | 숫자 | 전체현황 핵심지표 표시 순서 |

- 목표값 적용 우선순위: **해당 연월 목표 → 기본 목표 → 없음**.

### 2-5. 이슈 (Issues)
| 열 | 내부 이름 | 형식 |
|---|---|---|
| 제목 | Title | 텍스트 |
| 센터코드 | CenterCode | 텍스트 |
| 이슈일자 | IssueDate | 날짜 |
| 내용 | Content | 여러 줄 텍스트 |
| 확인여부 | Reviewed | 예/아니요(기본 아니요) — 관리자만 변경 |

### 2-6. 공휴일 (Holidays)
| 열 | 내부 이름 | 형식 |
|---|---|---|
| 날짜 | Title | 텍스트 `YYYY-MM-DD` |
| 이름 | HolidayName | 텍스트 |

2026년 등록값: 01-01, 02-16, 02-17, 02-18, 03-01, 03-02, 05-05, 05-24, 05-25, 06-03, 06-06, 07-17, 08-15, 08-17, 09-24, 09-25, 09-26, 10-03, 10-05, 10-09, 12-25

### 2-7. 알림설정 / 알림로그 / 결재요청
- 알림설정: 알림종류(실적미업로드 / 이슈미등록), 기준일수(기본 4), 발송시각, 반복주기(일), 메일제목, 메일본문, 발송정지(예/아니요)
- 알림로그: 센터코드, 알림종류, 경과일수, 수신자, 즉시발송여부, 성공여부, 실패사유, 발송시각
- 결재요청: 센터코드, 문서명, 회차(YYYY-MM), 입력값(JSON), 결재상태, 요청자, 승인자, 요청일시

### 3-4. LG전자통합 (lge_total)

실적(일별): TNPS, 생산성_INOUT, 생산성_IN, 통화시간_INOUT_초
실적(월평균, 그 달 1일 날짜에 저장): TNPS_월평균, 생산성_INOUT_월평균, 생산성_IN_월평균, 통화시간_INOUT_초_월평균

### 3-5. 평택시청 (pyeongtaek)
근태: 재직인원(전체 운영인력), 투입인원(그날 근무 상담사 수)
실적: 요청호, 응답호, 응대율, 포기호, CPD
업무유형별 건수: 일일업무보고 "건수" 행의 유형 이름 그대로(교통, 복지, 환경 … 지역경제 등 12종) + 합계
업무유형별 비중(계산값): `{유형}_비중` = 유형 건수 ÷ 합계 × 100

> ※ 이관 직후 `2-sharepoint/migration/export.sql`의 "지표키 목록" 결과로 이 장을 한 번 대조한다. 실제 키와 다르면 실제 키를 따른다.
