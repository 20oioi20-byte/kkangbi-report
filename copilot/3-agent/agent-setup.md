# Copilot Studio 에이전트 설정서

> 3단계. Copilot Studio(https://copilotstudio.microsoft.com)에서 아래 순서대로 만든다.
> 1단계 지식 문서와 2단계 SharePoint 목록, 4단계 흐름 중 **T1·T2**가 먼저 있어야 시험이 된다.

## 1. 기본 정보
| 항목 | 값 |
|---|---|
| 이름 | 센터리포트 |
| 설명 | 콜센터 6곳의 일별 실적·근태를 조회하고, 목표 대비 현황과 월간 보고서 초안을 만드는 에이전트 |
| 지침(Instructions) | `instructions.txt` 전체 붙여넣기(약 2,600자 — 한도 8,000자) |
| 언어 | 한국어 |
| 생성형 오케스트레이션 | **켬** (도구·지식 자동 선택) |
| 일반 지식 사용(Use general knowledge) | **끔** — 센터리포트 밖의 지식으로 답하지 않게 |
| 웹 검색 | **끔** |
| 인증 | Microsoft 인증(Authenticate with Microsoft) — `System.User.Email` 을 쓰기 위해 필수 |
| 게시 채널 | Microsoft Teams + Microsoft 365 Copilot |

## 2. 지식(Knowledge)
| 순서 | 파일 | 올리는 곳 |
|---|---|---|
| 1 | K1_업무정의서.docx | SharePoint `센터리포트/지식` 폴더 → 지식에 SharePoint 폴더로 연결 |
| 2 | K2_데이터사전.docx | 〃 |
| 3 | K3_센터별_추출규칙.docx | 〃 |
| 4 | K4_KPI_계산식.docx | 〃 |
| 5 | K5_운영규칙_알림_이슈_결재.docx | 〃 |

- `.docx` 는 `1-knowledge/docx/` 에 만들어 두었다(원본은 같은 폴더의 `.md`). 규칙을 고치면 `.md` 를 고치고 `python3 copilot/1-knowledge/build-docx.py` 로 다시 만든다.
- 파일 업로드 대신 **SharePoint 폴더 연결**을 권한다 — 문서를 고치면 다시 올리지 않아도 반영된다.
- 일별실적 **목록 자체는 지식으로 연결하지 않는다.** 숫자는 반드시 T2(KPI조회)로만 가져와야 하기 때문이다(목록을 지식으로 걸면 에이전트가 행을 읽고 직접 계산하려 한다).

## 3. 도구(Tools) — 4-automate/flows.md 의 T1~T7
| 도구 이름(에이전트에 보이는 이름) | 흐름 | 설명(에이전트가 언제 쓰는지 판단하는 문장) |
|---|---|---|
| 권한확인 | T1 | 모든 조회·변경 전에 사용자의 관리자 여부와 조회 가능한 센터 목록을 확인한다 |
| KPI조회 | T2 | 센터와 기간을 받아 핵심지표의 기간 값·누적·전월比·전년동월比·목표 판정을 계산해 돌려준다 |
| 업로드현황 | T3 | 센터별 마지막 업로드 시각과 신호등을 돌려준다 |
| 이슈조회 | T4 | 센터·검색어·미확인 여부로 이슈·히스토리를 찾는다 |
| 이슈등록 | T4 | 날짜·제목·내용으로 이슈를 등록한다 |
| 이슈확인 | T4 | (관리자) 이슈를 확인함/확인취소로 바꾼다 |
| 즉시발송 | T5 | (관리자) 미업로드 알림을 지금 조건에 맞는 센터에 바로 보낸다 |
| KPI목표저장 | T6 | (관리자) 센터·지표·연월의 목표값을 저장한다 |
| TO저장 | T6 | (관리자) 센터·연월의 관리자/상담사 TO를 저장한다 |
| 결재요청 | T7 | 결재 문서 값과 승인자를 받아 승인 요청을 보낸다 |

**입력 설정(중요)**
- 모든 도구의 `userEmail` 입력 → 「값 채우기 방식: **사용자 지정 값**」 → `System.User.Email`. **AI가 채우도록 두지 않는다.**
- `centerCode` 설명란: "kbsonhae, kbjeongbi, lge, lge_seongsu, lge_total, pyeongtaek 중 하나"
- `startDate`/`endDate` 설명란: "YYYY-MM-DD 형식"
- 변경 도구(이슈등록·이슈확인·즉시발송·KPI목표저장·TO저장·결재요청)는 「실행 전 사용자 확인 요청」을 켠다.

## 4. 시작 질문(Starter prompts)
1. 이번 달 KB손보부천 핵심지표 보여줘
2. 지난달 전 센터 현황을 표로 정리해줘
3. 업로드 안 된 센터 있어?
4. 평택시청 9월 월간 보고서 초안 써줘
5. LG전자AS 근태 파일은 어디에 어떻게 올려?
6. 미확인 이슈 요약해줘

## 5. 인수 시험(게시 전 반드시 통과)
| No | 계정 | 질문 | 통과 기준 |
|---|---|---|---|
| 1 | 관리자 | "지난달 KB손보정비 처리율" | 값이 현행 대시보드와 소수 첫째 자리까지 일치, Σ/Σ 방식 |
| 2 | 관리자 | "이번 달 LG전자통합 T-NPS" | 월평균 입력값 그대로(일별 평균 아님) |

| 4 | 센터담당자(부천) | "평택시청 실적 보여줘" | 권한 없음 안내, 숫자 없음 |
| 5 | 센터담당자(부천) | "제휴SL 목표를 85로 바꿔줘" | 관리자 전용 안내, 저장 안 됨 |

## 6. 운영 팁
- 답이 틀리면 먼저 **활동 지도(Activity map)** 에서 어떤 도구를 불렀는지 본다. 도구를 안 불렀으면 도구 설명 문장을, 불렀는데 값이 틀리면 흐름/스크립트를 고친다.
- 지침을 고친 뒤에는 위 인수 시험 10개를 다시 돌린다.
